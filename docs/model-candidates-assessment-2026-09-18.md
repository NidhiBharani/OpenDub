# Assessment of OpenDub's seven phases and 41 capabilities

Reviewed 18 September 2026 using three GPT-5.6 Sol subagents: A/B, C/D, and E/F/G. The main review checked cross-phase integration against `README.md`, `ARCHITECTURE.md`, `docs/plans/capability-map-implementation.md`, and the current capability registry. This is a design review with targeted primary-source verification, not an inference benchmark or an exhaustive audit of every model/version claim.

**Verdict: keep the seven-phase capability map, but revise the execution contracts and several model recommendations before treating it as an implementation specification.** The coverage is strong. The most valuable choices are the editable cascade, explicit timing work, separate identity and delivery signals, optional picture processing, preservation of original nonverbal sounds, and independent quality checks. Forty-one configurable capabilities is reasonable; forty-one mandatory sequential transformations would not be.

The companion implementation plan already addresses many practical concerns: presets, dependency resolution, supplied-M&E bypass, reference selection, a glossary/show bible, review queues, benchmark hooks, and experimental/deferred features. The changes below make those ideas concrete and correct remaining mismatches.

**The changes that matter most**

1. **Make voice generation one compatible request, with a bounded feedback loop.** D1 cloning, D2 expression, D3 duration, D4 language routing, and C5 pronunciation are jointly required properties of a take. The document recommends Fish for D1 and IndexTTS for D2/D3; these engines do not automatically compose. Give every provider an explicit capability matrix covering language, cloning, independent style reference, instructions, pronunciation controls, pace versus exact duration, and nonverbals. Choose a compatible route per character/language, preserve its identity across lines, and make unsupported controls visible. Use `C2 candidate → C4/rules → synthesis → actual duration and G1–G4 checks → bounded rewrite/regeneration → E1 residual fit`. Preserve accepted text and takes when retrying. See model document lines 1410, 1504, 1583 and 1630.

2. **Correct the exact-duration assumption.** The document describes IndexTTS 2.5 token-count control and predicts that passing `target_duration` eliminates stretching. The [official release README](https://github.com/index-tts/index-tts/blob/main/README.md) documents `duration_factor` pace control; the earlier precise-duration feature is described as not enabled in that release. Treat exact target duration as unverified until a released interface passes an integration test. Rejection sampling needs a retry limit, a failure outcome, and residual timing correction. A model accepting a pace knob does not guarantee a natural take of a requested length.

3. **Design an explicit anime route.** B1's human-face detector/active-speaker stack does not establish support for drawn characters. Classify and route individual shots, including hybrid content, off-screen speech, and uncertain cases. F3's decision to avoid automatic regeneration of 2D mouths is sensible. However, [Rhubarb](https://github.com/DanielSWolf/rhubarb-lip-sync) generates mouth cues from audio; it does not observe the mouth flaps already drawn in a video. Actual flap-aware C3 adaptation needs visual mouth-state evidence or manual timing marks. It should work with picture lip sync disabled: the current C3 registry entry instead requires `lipsync` and B1 (`server/app/capabilities.py`, lines 147–150).

4. **Strengthen source and timeline contracts.** A diarization overlap mask identifies a problem; it does not recover two simultaneous transcripts or clean speaker references. Add a conditional overlap branch for speaker extraction and per-speaker ASR, with unresolved alternatives sent to review. Preserve transcript role and language: ASR hypothesis, verbatim source script, translated subtitle, condensed caption, and approved dub script are different artifacts. A5 must not force-align a translated or condensed subtitle as though it were verbatim source speech. Keep one authoritative source timeline, source-word lineage, and a separate realized timeline for each generated take. C6 subtitles and downstream artifacts must be invalidated when a retry changes approved speech.

5. **Treat judges as calibrated selection tools.** Independent ASR, identity versus perceptual similarity, and decomposed review are good choices. But benchmark correlation or ranking ability does not supply an automatic acceptance threshold for anime. Calibrate by language, utterance length, and delivery style; include whispers, shouts, cries, laughter, music, names, and code-switching. Apply hard content/timing constraints before ranking naturalness and expression, and allow abstention. Use a held-out evaluator and human sample that were not used to select the takes. Otherwise increasing best-of-N can improve the selected metric without improving the dub.

6. **Correct model readiness and metric applicability.** F2 calls DVFace code public, but the [official repository](https://github.com/zhengchen1999/DVFace) still lists testing code and pretrained models as release TODOs. Keep it on the research list and use a released restoration/compositing route. G5 promotes PEAVS to a primary lip-sync judge, but its [official benchmark](https://github.com/amazon-science/avgen-eval-toolkit) explicitly excludes faces. Its reported correlation therefore does not establish speech-mouth alignment quality. Use speech-specific per-face metrics, validated on the target footage, with PEAVS supplementary. See model document lines 2768 and 3317.

7. **Validate the delivered file.** The implementation plan puts review before render and F4 text replacement inside render. That leaves text edits and encode/mux errors outside the review. Keep intermediate judges, then add validation of the final decoded deliverable: tracks, duration/drift, clipping/true peak, subtitles, text legibility, and visible edits. Derive dialogue measurement intervals from final dub activity, not unmodified A4 source-word timings. E4's deterministic measurement is sensible, but measurement conformance does not solve expressive leveling or mix balance. E5 remains deferred as already decided; when implemented, C2PA must bind the final asset and watermark detection must be checked after the complete processing/encoding chain.

**Assessment of all 41 capabilities**

“Keep” endorses the capability and basic strategy, not an unbenchmarked claim that its named model is best. “Conditional” means run only when applicable. “Revise” means its contract, evidence, or default needs correction.

| Phase / ID | Capability | Verdict and required refinement |
|---|---|---|
| A1 | Dialogue/music/effects separation | **Keep.** Prefer supplied stems where available; measure dialogue leakage and damage to the retained bed, preserve channel layout, and verify sample-aligned reconstruction. |
| A2 | Reference enhancement | **Conditional.** Select clean, isolated speaker windows first; enhance only when content and identity improve. Retain raw references and an override. |
| A3 | Speech/music/singing classification | **Revise.** Use overlapping, multi-label regions with confidence and an explicit pass/dub/review action; singing, speech, laughter, and music can coexist. |
| A4 | Transcription and word timing | **Keep.** Test anime speech and hallucinations under music. Record language, confidence, and timing provenance; ASR and aligner language coverage can differ. |
| A5 | Forced alignment | **Keep with a narrower contract.** Align verified same-language text and reconcile disagreements with ASR into one timing artifact; avoid silently duplicating A4 alignment. |
| A6 | Diarization and overlap | **Revise.** Preserve simultaneous speakers and unknown assignments; add extraction/re-ASR or review for overlap, and verify checkpoint eligibility before selecting a default. |
| A7 | Embeddings and voice-bank matching | **Keep, remove “solved.”** Acoustic speaker identity is not character identity: one actor may play multiple roles. Add abstention, manual aliases/merge/split, and domain calibration. |
| A8 | Delivery tagging | **Keep measured features; experiment with descriptions.** Normalize pitch/rate relative to each character and test whether generated delivery notes actually improve synthesis. |
| B1 | Active speaker and face tracking | **Conditional.** Use the human-face route only on supported shots; represent off-screen speech, ambiguous faces, and track changes explicitly. |
| B2 | Shot detection | **Keep and run early.** Preserve presentation timestamps and transition spans; test flashes, title cards, dissolves, and animation cuts. |
| B3 | OCR | **Keep specialist OCR plus temporal tracking.** Test vertical Japanese, furigana, stylized signs and credits; distinguish on-screen text from dialogue and review uncertain glossary additions. |
| B4 | Content type | **Keep as an essential gate.** Persist shot-level routing and uncertainty; one project-wide content label cannot describe hybrids. |
| C1 | Dub-line segmentation | **Keep, make provisional.** Start from pauses and word timing, preserve interruptions/overlap, and permit controlled repair after translation or measured TTS duration. |
| C2 | Translation and adaptation | **Keep, benchmark on dubbing.** Scene meaning, character register, names and continuity precede line-length optimization. Select scene-consistent variants rather than independently optimizing every sentence. |
| C3 | Viseme adaptation | **Experimental.** Give semantics priority; calibrate phonetic costs by content type. Anime flap matching needs actual visual evidence and must work without pixel lip sync. |
| C4 | Translation QE | **Keep for ranking and triage.** Generic MT quality does not measure acting, timing, or character consistency. Calibrate acceptance and audit apparently good results too. |
| C5 | Normalization/G2P/lexicon | **Keep.** Separate display/semantic text from spoken text, then compile pronunciation hints into each provider's supported representation. |
| C6 | Subtitle condensation | **Conditional and distinct from dub adaptation.** Reading speed and spoken duration are different constraints. Derive subtitles from the approved version and retime after speech changes; consider ASS if preserving anime styling is required. |
| D1 | Cross-lingual cloning | **Keep; validate the production default.** Freeze a curated character profile, test expressive cross-lingual identity and accent, and distinguish an evaluation winner from a deployable default. |
| D2 | Expression/style transfer | **Keep within the joint synthesis contract.** Independent identity/style conditioning is useful; test timbre, accent, noise and room leakage from style references. |
| D3 | Duration control | **Revise.** Distinguish pace from exact duration; measure generated output, use bounded retries and script repair, and retain a residual stretcher. |
| D4 | Language routing | **Conditional.** Route by language plus required voice/style/pronunciation/timing controls, backed by per-language acceptance results and stable casting. |
| D5 | Stock/non-cloning voices | **Keep the mode; revise the rationale.** Text-designed voices are a casting method, not evidence of rights clearance. Record actual provider/voice terms and freeze the auditioned identity. |
| D6 | Voice conversion | **Advanced fallback.** Useful for human takes and difficult vocal material; compare against direct re-synthesis and check content/identity leakage. |
| D7 | Nonverbal vocalizations | **Keep splice-first.** Reject source-language contamination and mixed-speaker regions; use accurate boundaries, crossfades and scene matching. A detected event alone is not a splice-ready asset. |
| D8 | Direct S2ST | **Keep benchmark-only.** Compare editability and language coverage as well as quality. UniSS's English/Chinese support does not by itself benchmark Japanese-anime dubbing. |
| E1 | Timing and pauses | **Keep.** Use realized target timing and meaningful phrase pauses, preserve interruptions, bound stretch, and escalate failed fits to rewrite/regeneration or review. |
| E2 | Bandwidth/restoration | **Conditional.** Resampling is not restoration; process only diagnosed degradation and reject introduced phonemes, timbre changes or texture mismatch. |
| E3 | Scene acoustics | **Conditional.** Start with inspectable EQ, room/effect parameters and scene-consistent settings; verify learned estimator/checkpoint availability before adopting a paper recipe. |
| E4 | Leveling/loudness | **Keep, broaden acceptance.** Measure final dialogue and mix, preserve intentional dynamics, validate channel layout and true peaks; conformance alone does not establish a good mix. |
| E5 | Provenance | **Keep deferred.** Bind the final deliverable and verify watermark survival after processing/encoding when the milestone is implemented. |
| F1 | Live-action lip sync | **Conditional.** Route per supported shot/face, use clean target-speaker audio where appropriate, preserve unmodified pixels, and check identity, expression, boundaries and temporal stability. |
| F2 | Mouth restoration | **Revise primary; conditional capability.** DVFace is not a released runnable dependency in the checked repository. Start with conservative feathering, color/grain matching and a released fallback. |
| F3 | 2D mouth retiming | **Keep the honest decline/export behavior.** Rhubarb supplies desired audio-derived mouth cues; existing-flap observation and retiming remain separate work. |
| F4 | On-screen text replacement | **Advanced/conditional.** Keep overlay/template export as the default. Prefer exact shaped-font rendering plus tracked compositing for replacement text; reserve generation for difficult erasure/style reconstruction and review it. |
| G1 | Intelligibility | **Keep.** Use independent ASR families and language-appropriate error normalization; separate the take selector from the final evaluator and check omissions/repetitions. |
| G2 | Voice similarity | **Keep identity and perceptual scores separate.** Calibrate on character profiles and short expressive clips; add consistency with adjacent accepted takes. |
| G3 | Naturalness | **Keep as a relative signal.** Calibrate for expressive/short/nonverbal material, use disagreement to trigger review, and keep distribution-level evaluation out of per-line acceptance. |
| G4 | Emotion consistency | **Advisory until calibrated.** Cross-language expression and stylized acting require target-domain validation; do not let a numeric emotion match reward unnatural delivery. |
| G5 | Lip-sync scoring | **Revise the primary metric.** PEAVS evidence is not face/lip validation. Use suitable per-face speech metrics with confidence and content-type gates; anime needs its own protocol. |
| G6 | Multimodal review | **Keep for defect triage.** Use localized evidence and a fixed rubric, calibrate against human review, and include the final deliverable rather than only intermediate clips. |

**Evidence and compute assumptions**

The document mixes architectural proposals, paper results, available products, and estimated Spark performance. Give each candidate separate fields for released artifact/version, checkpoint license, supported language/control combinations, installation status, measured peak memory, measured latency, and OpenDub quality evidence. Mark these as verified, inferred, or untested. A research result should not become an executable primary solely because its parameters fit memory.

[NVIDIA confirms](https://www.nvidia.com/en-us/products/workstations/dgx-spark/) the 128 GB unified memory and 273 GB/s bandwidth. Those specifications do not validate per-model runtime estimates, co-residency, or best-of-N throughput. The document's blanket single-digit LLM claim also needs qualification for dense versus sparse models and quantization; later sections already describe much faster sparse-model cases. Keep the Spark profile separate from the companion implementation plan's 16 GB GPU profile.

Several conclusions should be softened from “solved” or “at the ceiling” to “little demonstrated benefit from additional compute in the cited evaluations.” Comparison across different architectures, datasets and training recipes is not a controlled scaling study. The 1–5 score also mixes model capacity, sampling throughput, task maturity and API availability; separate those axes before using it to allocate effort.

Additional source corrections from the targeted checks:

- [Fish's inference documentation](https://github.com/fishaudio/fish-speech/blob/main/docs/en/inference.md) recommends at least 24 GB, while the document estimates about 11 GB. That is not proof of a measured minimum, but the difference needs an actual Spark run. Its [S2 weights license](https://huggingface.co/fishaudio/s2-pro/blob/main/LICENSE.md) also needs to be represented in provider eligibility rather than left as a future question.
- [DiariZen](https://github.com/BUTSpeechFIT/DiariZen) separates MIT code from pretrained weights labeled CC BY-NC 4.0. Apply the companion plan's existing default-provider policy to the exact checkpoint.
- The [UniPASE paper](https://arxiv.org/abs/2604.14606) describes a 48 kHz PostNet after 16 kHz reconstruction. The A2 discussion should not treat 16 kHz as an unconditional final-output ceiling.
- [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) separates Base, CustomVoice and VoiceDesign variants. Capability support must be recorded for the chosen variant, not inferred from the model family name.
- [UniSS](https://github.com/cmots/UniSS) documents English and Chinese support. Label the benchmark scope accordingly.

**A practical implementation sequence**

1. Establish typed source/take artifacts, timing/provenance, overlap semantics, provider capability negotiation, reproducible configurations, and a small held-out anime evaluation set. Include source/translation edits and targeted regeneration in the pilot.
2. Complete one real Japanese-to-English route: reliable source analysis and references; context-aware translation/lexicon; one jointly capable synthesis provider; G1/G2; bounded timing correction; preserved nonverbals; mix and final-file validation. Judge whole scenes as well as individual lines.
3. Add calibrated take selection, translation/emotion/naturalness triage, subtitle export, scene acoustics, and additional language/provider routes only when they improve the pilot's output. Retain unprocessed alternatives for optional restoration.
4. Add live-action lip sync, picture restoration and text replacement as distinct optional products. Keep 2D regeneration and direct S2ST experimental, and keep provenance in its already deferred milestone.

The acceptance result should report both quality and intervention: missed words/meaning, wrong character assignment, voice drift, timing failures, bed damage, visible edits, and how many lines still require manual work. Lock a held-out set by title, use bilingual review for translation, and compare against the current pipeline under the same conditions. That evidence will make model swaps and additional compute useful engineering decisions rather than leaderboard substitutions.
